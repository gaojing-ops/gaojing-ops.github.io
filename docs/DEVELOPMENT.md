# 长夜余烬开发说明

## 本地运行与入口

在仓库根目录运行 `python -m http.server 8000`。

- `/`：根目录 `index.html`，使用 `/games/emberfall/` 下的脚本和样式。
- `/games/emberfall/`：游戏目录 `index.html`，使用相对路径加载同一套脚本和样式。

修改界面结构时检查两个 HTML 入口；修改共享脚本或样式会同时影响两个入口。使用 HTTP 打开，浏览器需要加载 ES 模块。GitHub Pages 直接托管静态文件，没有构建步骤。

## 模块与数据

`game.js` 的 `createGame(canvas, hooks)` 管理模拟、Canvas 渲染及输入，提供 start、pause、resume、chooseUpgrade、dash、setMovement、getSnapshot 和 destroy 等方法。引擎通过 onState、onStats、onUpgrade、onEnd、onToast 通知界面。

`app.js` 管理角色选择、DOM 状态、弹窗、触屏摇杆及战绩。localStorage 键为 `gaojing-emberfall-v1`，保存累计统计、最近 10 次结算与音效设置，不保存进行中的远征。写入失败时仅保留当前页面内存中的记录。

## 状态与输入约定

- `ready` → `playing`：开始远征。
- `playing` ↔ `paused`：暂停、继续；窗口失焦或页面隐藏时暂停并清空移动输入。
- `playing` → `upgrade` → `playing`：升级暂停模拟，选择后继续；积累多级经验时会连续进入升级。
- `playing` → `won` / `lost`：结算；重玩会重置本局数据，返回营地销毁旧引擎并新建。

玩法、图鉴、战绩弹窗会暂停进行中的战斗；若打开弹窗后页面失焦，关闭弹窗不会自动恢复战斗。

引擎处理移动与冲刺，界面处理暂停和升级数字快捷键。两者都应忽略 Ctrl / Alt / Meta、输入法组合输入、编辑区域和已处理事件。空格在按钮或链接上保留原生激活行为；在画布上触发冲刺。继续战斗后焦点回到画布。

## 结算与升级边界

结算发生后停止本帧剩余战斗更新，`hurtEnemy` 也必须拒绝非 playing 状态的伤害。否则连锁闪电或穿透弹可能在 onEnd 后继续增加击杀，治疗拾取也可能把死亡生命值重新抬高。

所有强化满级且治疗不满足常规出现条件时，用“灯下小憩”作为保底选项，避免升级界面没有可选卡牌。保底允许在满血时选择以继续游戏。

## 验证

Node.js 22+，无需安装依赖：

```sh
node --test tests/game.test.mjs tests/blessings.mjs tests/touch-controls.test.mjs
node --check games/emberfall/game.js
node --check games/emberfall/app.js
git diff --check
```

测试通过 VM 为实际引擎注入仅测试可见的状态访问器，模拟 Canvas 和事件环境，覆盖键盘事件、输入清理、满级升级、胜负结算边界。生产脚本不暴露测试接口。测试不验证真实绘制、音频或浏览器指针捕获。

手动检查两个入口：选择角色、开始、画布空格冲刺、焦点在暂停按钮时按空格、继续后焦点回到画布、P / Esc 暂停、弹窗打开关闭、返回营地。手机还需检查摇杆拖动/松开、冲刺、横竖屏、升级卡牌滚动；完成一局后检查战绩并刷新确认本地保存。

本轮验证：8 项引擎测试通过；同一组测试在修复前版本有 7 项失败。浏览器已验证根入口的空格暂停、继续焦点、玩法弹窗及 390 px 宽度下冲刺与暂停。手机真机多点触控、完整三分钟通关与跨刷新战绩仍需实机验收。

## 神明赐福与闪避冷却

`game.js` 导出 `DEITIES`，统一维护五位神明的名称、配色与强化归属。升级优先给出不同神明的选项，强化池不足时复用神明，完全满级时保留治疗保底。五项专属赐福分别提供灼烧、机动、暴击、减速和恢复效果，可与原有强化叠加。

人物脚下的闪避条直接读取 `dashCooldown / dashMax`，跟随人物且保持屏幕像素大小；倒计时向上取一位小数，避免尚不可用时显示 0.0 秒。暂停和升级选择停止冷却，重新开局清空赐福。

`tests/blessings.mjs` 覆盖神明归属、灼烧叠加、减速、暴击倍率、恢复、减冷却叠加、暂停、冷却条文本、不同神明选项、满级保底与重开重置。与原有八项回归测试一起运行；VM 适配器移除模块导出，不改变正式接口。浏览器已验证赐福选择、风神减冷却、构筑归属和闪避条；手机真机多点触控与完整通关仍待实机验收。

## 浮动摇杆与战斗内赐福

`touch-controls.js` 在战斗画面空白处的 pointerdown 位置建立摇杆原点，由 game-stage 捕获单一移动指针。其他指针保持独立，可继续点击闪避；按钮和弹窗不会启动摇杆。抬手、pointercancel、lostpointercapture、暂停、失焦、全屏切换和窗口尺寸变化都会释放捕获并清零移动。

战斗上方的赐福栏横向滚动显示当前升级名称和等级；“详情”使用现有弹窗，显示所有持续赐福、每层效果、当前生命上限和实际闪避冷却。从战斗中打开会暂停，正常关闭后继续；在升级或原本暂停时打开不会绕过原有状态。即时治疗不计入持续赐福。

`tests/touch-controls.test.mjs` 覆盖不同触点、死区与速度上限、第二指针隔离、按钮与非主键过滤、取消与捕获丢失、暂停/尺寸变化时的清理。真机多点触控仍需实机验收。
